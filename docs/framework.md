# 明鉴 · AI 演示生成评估标准

**Open Presentation-generation Evaluation Standard (OPES)**

> 版本 v0.1 ｜ 日期 2026-07-01
> 适用范围：一切"由 AI 生成/编码方式产出演示（PPT / 网页 deck / 可导出文档）"的工具与场景——豆包、Kimi、Codex、Genspark、Manus、天工 Skywork、Gamma、AiPPT 等横向可比。
> 定位：一把**公开、中立、可复现**的尺子。它既评"最终做出来的演示好不好"，也评"这个工具在生成过程中好不好用"。

## 0. 这份标准要解决什么问题

今天每个人测评 AI 生成 PPT，都在用自己临时拍的标准：博主凭手感、开发者凭跑分、企业凭一次 demo 的印象。结果是——**没有一把三方都认的尺子**，谁的结论都可以被一句"你的标准有偏向"推翻。

本标准的目标，是做一套让三类人**都认可其方法本身站得住**的评估框架：

| 使用者 | 他要的 | 本标准给他的 |
|---|---|---|
| **自媒体 / 测评人** | 一眼能感知、能排名、能传播 | 快速人工版 + 总分/雷达图 |
| **工具开发者 / 技术评测** | 客观、可复现、无法被说"不公" | 严谨复现版 + 盲评协议 + 客观指标 |
| **企业采购决策者** | 能落地、能过合规、能写进采购结论 | 采购权重档 + 可移交/数据安全维度 + 自评手册 |

一个关键设计取舍：**本标准只规定"怎么量"，不替任何人打分。** 分数永远来自评估者自己的主客观评价。这样任何一方都可以拿去自己测、得出自己的结论——包括测评标准的发起者自己。

## 1. 设计原则（为什么它值得被信任）

这七条是本标准的"宪章"。它们不是修辞，是让一份评估在被质疑"你是不是偏心"时依然站得住的工程约束。

1. **作者中立、身份透明。** 标准的可信不靠"隐藏作者"，而靠"公开作者 + 公开安全设计"。任何参与方（含厂商）应在报告中披露自己与被测工具的利益关系。利益相关方参与评分时，其分数需与独立评分者交叉核对。
2. **没有"主场维度"。** 任一维度若只奖励某一家的独有强项、而结构性地压制其他路线，即视为设计缺陷。框架**必须包含作者自己会输的维度**（例如公有云最强模型在"视觉惊艳度""模型马力"上通常胜过可私有化部署方案）——一份作者永远全赢的量表，不具可信度。
3. **客观优先。** 能测量的一律测量（时延、返工次数、导出成功率、对比度、字号、单页字数、单份成本…），尽量减少"可被说成主观拿捏"的空间。每个指标明确标注 **O（客观可测）/ H（半客观，可测但需判断）/ S（主观，需评审打分）**。
4. **主观必配锚点 + 多人盲评。** 凡主观项，一律给 1/3/5 文字锚点；正式评测采用盲评（隐去工具名）、多名评分者、报告评分者一致性（inter-rater agreement）。
5. **权重可配置、不写死。** 框架给出若干"权重档"作为建议，但权重是**使用者可调、且理由须透明**的选择。任何"内置了对自己有利的权重"的指控，都因权重公开可改而失效。
6. **短板可见，拒绝平均掩盖灾难。** 除总分外，必须同时报告**维度明细 + 最差项/最差页**。"视觉满分 + 配图张冠李戴"绝不等于"平均还行"。设**硬否决项**，触发即封顶。
7. **可复现、可追溯。** 固定题集、同一提示词、公开评分过程与原始数据。任何人应能用相同输入复现结论（允许合理波动）。

> 一句话：**把尺子做得足够公平，公平到使用者哪怕测到"作者自己"也照样信这把尺子。**

## 2. 评估模型：三层 · 九维

一份 PPT 不是文档，是**一次发生在特定场景里的沟通行为**。所以不能只评"成品"，必须同时评"产出成品的过程"和"能不能放心地规模化用它"。据此，本标准把评估切成三个层面、共九个维度：

```
┌──────────────────────────────────────────────────────────────┐
│                    一次成功的 AI 演示生成                        │
├──────────────────┬──────────────────┬────────────────────────┤
│    层一 · 成品力    │    层二 · 生成力    │      层三 · 可信力        │
│   The Artifact    │   The Process     │     Trust & Fit         │
│   成品本身好不好     │   过程顺不顺、快不快  │   能不能放心、规模化地采用   │
├──────────────────┼──────────────────┼────────────────────────┤
│  1  内容质量        │  4  交互与可控      │  7  稳定与一致性          │
│  2  视觉设计        │  5  效率           │  8  数据 · 安全 · 合规     │
│  3  表达适配        │  6  交付与可移交     │  9  成本与规模            │
└──────────────────┴──────────────────┴────────────────────────┘
      普通人一眼可感知           工具体验的核心          企业采购的关切
```

**为什么是这三层：**
- **成品力** 是所有人的公约数，也是"普通人一眼认可"的落点——博主测评八成的镜头都在这里。
- **生成力** 是被大多数只看成品的评测漏掉的一整面：它评"工具"而非"作品"——好不好懂你、快不快、能不能改、拿到手能不能真用起来。
- **可信力** 是把评测从"玩具好玩"抬升到"生产可用"的分水岭，也是企业采购真正下决心的地方。它天然中立：公有云工具在"数据不出内网"上会诚实地失分，可私有化方案在"开箱惊艳"上也会诚实地失分。

| 层 | 维度 | 一句话评什么 |
|---|---|---|
| **成品力** | 1 内容质量 | 说得对不对、透不透、有没有价值 |
| | 2 视觉设计 | 看上去好不好、专不专业 |
| | 3 表达适配 | 是不是一份"能上台讲"的演示，而非"好看的网页/文档" |
| **生成力** | 4 交互与可控 | 懂不懂我、好不好上手、能不能改到我要的 |
| | 5 效率 | 快不快、一次成不成、稳不稳 |
| | 6 交付与可移交 | 拿到手能不能真的编辑、导出、上台、嵌入 |
| **可信力** | 7 稳定与一致性 | 换个题、批量做，还稳不稳、一不一致 |
| | 8 数据·安全·合规 | 数据去哪、能不能私有部署、合不合规 |
| | 9 成本与规模 | 单份多少钱、能不能规模化、协作贵不贵 |

## 3. 维度细则与评分锚点

每个维度含若干**子指标**，每项按 **1–5 分**评（5/3/1 为锚点，4/2 插值）。标注 **O/H/S**（客观/半客观/主观）。维度分默认取子指标均值（可加权，见 §4）。列出的**硬否决项**一旦触发，整份直接封顶（见 §4）。

### 层一 · 成品力

#### 维度 1｜内容质量 — 说得对不对、透不透
| 子指标 | 类型 | 说明 |
|---|---|---|
| 事实准确性 | O | 与用户上传源/公开事实一致；数据、引用、时效可核查 |
| 结构与逻辑 | H | 有清晰主线；分点 MECE、不重不漏；论证链成立 |
| 信息密度（高度） | S | 恰当提炼——不是把资料整段搬进去，也不是空到没内容 |
| 洞察与价值 | S | 有超出"复述"的观点/结论/"so what"，而非正确的废话 |
| 意图忠实度 | H | 答的是用户真正问的题、主题贴合、覆盖关键要求 |

**5**：事实零错、逻辑清、提炼到位且有洞察，紧扣意图。 **3**：大体正确但平淡/密度失衡/覆盖有缺。 **1**：出现事实错误或跑题、堆砌未提炼。
**硬否决**：编造事实或数据造假；严重曲解上传源材料。

#### 维度 2｜视觉设计 — 看上去好不好、专不专业
| 子指标 | 类型 | 说明 |
|---|---|---|
| 美感与专业度 | S | 观感专业，不"模板廉价感"；风格成立 |
| 版式与层级 | H | 对齐、留白、字号层级、可读性（对比度/字号可测） |
| 风格一致性 | H | 全篇配色/字体/间距/组件统一 |
| 配图与图表准确性 | H | 图表/配图与内容对得上、数据可视化正确、不误导 |
| 无低级瑕疵 | O | 无溢出、截断、重叠、占位符（lorem/示例图未替换） |

**5**：专业、统一、无瑕、图文精准。 **3**：整体过关但有零散瑕疵/一致性瑕疵。 **1**：明显廉价/混乱/大量瑕疵。
**硬否决**：配图张冠李戴或严重误导（图表数据与文字矛盾、错配主体）。

#### 维度 3｜表达适配 — 是"演示"还是"网页/文档"
| 子指标 | 类型 | 说明 |
|---|---|---|
| 单页信息负载 | H | 一页一核心、可被"讲"，而非塞满的文档页 |
| 叙事节奏 | S | 有起承转合、章节节奏、有开场与收束，演讲者能顺着讲 |
| 场景/受众适配 | S | 贴合体裁（路演/汇报/教学/发布/数据报告）与受众语气、正式度 |
| 呈现距离可读性 | O | 关键信息在演示距离下可读（字号/对比达标） |

**5**：明显为"上台演示"而作，节奏与场景都对。 **3**：能看但更像文档、节奏平。 **1**：满屏文字、无法演示。

### 层二 · 生成力

#### 维度 4｜交互与可控 — 懂不懂我、能不能改
| 子指标 | 类型 | 说明 |
|---|---|---|
| 需求理解与澄清 | S | 读得懂 brief；必要时会追问，而非盲猜 |
| 易上手 | S | 新手无需教程即可产出第一版；引导清晰 |
| 可干预/可控 | H | 能指定风格/结构/品牌/篇幅；能局部重生成而非只能全推翻（功能有无=O） |
| 修改成本 | H | 改一处的代价——是局部编辑，还是必须重跑全篇 |

**5**：懂我、好上手、能精准局部调。 **3**：能用但改起来费劲/只能整体重来。 **1**：不懂需求、无法有效干预。

#### 维度 5｜效率 — 快不快、一次成不成
| 子指标 | 类型 | 说明 |
|---|---|---|
| 生成时延 | O | 从提交到拿到第一版可用稿的墙钟时间（计时） |
| 一次成型率 | H | 首版即达可用、无需大改的比例 |
| 返工次数 | O | 到"可接受"所需轮次（计数） |
| 过程稳定性 | O | 不崩溃、不超时、不半途失败 |

**5**：快、一次成、零卡壳。 **3**：速度或成型率一般、需一两轮。 **1**：慢/反复失败/多轮仍不达标。

#### 维度 6｜交付与可移交 — 拿到手能不能真用起来
> 本维度是"形态无关"评测的关键：无论产物是 HTML 网页 deck 还是可导出 PPTX，都在这里被诚实衡量。

| 子指标 | 类型 | 说明 |
|---|---|---|
| 二次可编辑性 | O | 能否再编辑：在线编辑器？导出可编辑 PPTX/Keynote？还是"死网页"只能看 |
| 导出与兼容 | O | 可导出格式（PPTX/PDF/PNG/HTML）；跨端/跨软件不走样 |
| 演讲态可用 | O | 全屏放映、演讲者视图、备注、离线可放 |
| 嵌入/分享/协作 | O | 链接分享、嵌入 OA/门户、多人协作 |
| 无锁定 | O | 内容可带出，不被平台绑死 |

**5**：可编辑、可导出、可演讲、可嵌入、无锁定。 **3**：部分可用（如只能看网页/导出会走样）。 **1**：拿到手基本无法融入既有工作流。

### 层三 · 可信力

#### 维度 7｜稳定与一致性 — 换题、批量还稳不稳
| 子指标 | 类型 | 说明 |
|---|---|---|
| 跨主题稳定 | H | 换不同题材/体裁质量不塌方（需多样题集） |
| 批量一致性 | H | 大批量产出时品牌/风格保持一致（企业量产关键） |
| 失败下限 | O | 最差 case/最差页能差到哪、灾难率多高 |
| 可复现性 | O | 同一提示词多次跑，质量方差小 |

**5**：不挑题、批量稳、下限高、方差小。 **3**：主力题材稳但偏题材会塌/偶发翻车。 **1**：看运气、下限灾难。

#### 维度 8｜数据 · 安全 · 合规 — 数据去哪、能不能私有
> 本维度对个人/自媒体可降权甚至归零，对企业则是生死线。它天然中立：纯云端工具会在此诚实失分，可私有化方案会在此得分——反之在"视觉惊艳"等维度则相反。

| 子指标 | 类型 | 说明 |
|---|---|---|
| 数据流向与隐私 | O | 内容是否离开你的网络？在哪处理/存储？可否关闭训练留存 |
| 私有化/本地部署 | O | 能否 on-prem / VPC 内 / 离线运行 |
| 合规与信创适配 | O | 数据合规、等保、国产化/信创软硬件适配 |
| 品牌与内容管控 | H | 品牌规范锁定、模板治理、内容审核（企业级） |
| 权限与审计 | O | 访问控制、操作审计日志 |

**5**：可私有部署、数据不出域、合规齐备、管控完善。 **3**：有企业管控但数据仍需出域/私有化有限。 **1**：数据必然外发、无管控。
**硬否决（仅在"私有化/合规"评测场景启用）**：声称私有/不外泄，实测数据出域。

#### 维度 9｜成本与规模 — 单份多少钱、能不能铺开
| 子指标 | 类型 | 说明 |
|---|---|---|
| 单份成本 | O | 每份 deck 的花费（积分/订阅摊薄/API/算力折算） |
| 规模化经济性 | H | 全员/团队铺开时的边际成本 |
| 协作与团队能力 | O | 席位、共享素材库、团队工作流 |
| 可及性 | H | 起步门槛：免费额度、注册门槛、学习成本 |

**5**：单份便宜、规模经济好、团队能力齐。 **3**：个人可承受、规模成本一般。 **1**：贵/难规模化/无团队能力。

## 4. 计分机制

**1. 子指标 → 维度分。** 每子指标 1–5；维度分 = 子指标（可加权）均值，换算为百分制 `维度% = 维度均分 / 5 × 100`。

**2. 维度 → 总分。** 总分 = Σ(维度% × 维度权重)，权重见 §5，合计 100。

**3. 硬否决（短板决定）。** 触发任一硬否决项，整份**评级封顶为 C / "不合格"**，无论总分多高。硬否决清单：
- 内容：编造事实 / 数据造假 / 严重曲解源材料
- 配图：张冠李戴 / 严重误导
- 交付：产物打不开 / 大面积排版崩坏 / 无法使用
- 数据（私有化·合规场景）：声称私有却数据出域

**4. 双报告，拒绝平均掩盖灾难。** 每次评测必须同时给出：
- **总分 + 评级**（用于排名/传播）
- **九维雷达图 + 最差项/最差页清单**（用于归因）。任一维度低于其满分 60% 即标红为"灾难维度"。

**5. 评级门槛：**

| 评级 | 条件 |
|---|---|
| **S** | 总分 ≥ 90，且无硬否决，且无灾难维度（各维度 ≥ 60%） |
| **A** | 总分 80–89，且无硬否决 |
| **B** | 总分 65–79，且无硬否决 |
| **C** | 总分 < 65，或触发任一硬否决 |

> 评级永远与"无硬否决"绑定——这是本标准区别于"堆总分"评测的核心：**一票否决的短板，不能被其他维度的高分买单。**

## 5. 权重档（建议值，使用者可调）

同一份九维打分，套不同权重即得不同视角的总分。以下四档为**建议起点**，任何使用者都可按自己场景调整——**权重公开可改，正是"没有内置偏向"的证明**。

| 维度（满分） | 通用横评 | 自媒体·体验向 | 企业·采购向 | 技术·复现向 |
|---|---:|---:|---:|---:|
| 1 内容质量 | 20 | 15 | 20 | 20 |
| 2 视觉设计 | 15 | 25 | 10 | 12 |
| 3 表达适配 | 10 | 10 | 10 | 8 |
| 4 交互与可控 | 10 | 10 | 7 | 8 |
| 5 效率 | 10 | 15 | 5 | 12 |
| 6 交付与可移交 | 10 | 5 | 10 | 10 |
| 7 稳定与一致性 | 10 | 10 | 13 | 18 |
| 8 数据·安全·合规 | 8 | 0 | 15 | 7 |
| 9 成本与规模 | 7 | 10 | 10 | 5 |
| **合计** | **100** | **100** | **100** | **100** |

**各档理由：**
- **通用横评** — 三层大体均衡，成品力略重（毕竟 PPT 的目的是成品）。用于"谁最好"的公开横评与传播。
- **自媒体·体验向** — 重"一眼好看 + 快 + 好上手"，弱化合规；成本只看"免不免费、好不好起步"。
- **企业·采购向** — 重"内容准确 + 落地可移交 + 批量一致 + 数据安全 + 成本"，视觉惊艳降权。**这一档下，"数据不出内网、批量一致、可移交"占大头，谁在这些轴上强，谁就赢——由使用者自己的题和自己的评分得出，而非标准替他背书。**
- **技术·复现向** — 重可复现/稳定与客观指标，用于开发者/第三方技术评测。

## 6. 两种评测模式

同一套维度与锚点，按投入产出分两档执行。**结论可跨模式比较**，只是置信度不同。

### 模式 A｜快速人工版（自媒体 / 快速横评）
- 1 名评测者，约 30–60 分钟/工具。
- 每维度只打维度总分（可略过部分子指标），补几项客观测量（时延、导出成功、单份成本）。
- 产出：总分 + 雷达图 + 最差项。适合社媒测评与初筛。
- 局限：主观、单人、非盲——须在报告中如实标注。

### 模式 B｜严谨复现版（开发者 / 企业采购 / 官方横评）
借鉴成熟评测流水线的严谨度，把"可信"落到操作层：
1. **固定题集 + 同一提示词** 投喂所有工具（见 §7）。
2. **盲评**：隐去工具名后再渲染、再评分。
3. **多人独立评分**：每样本 ≥ 2 名评分者独立打分；分歧样本（差异 > 20% 或评级不一致）交仲裁定稿。
4. **一致性校验**：报告评分者一致性（如 ρ ≥ 0.7 视为可信），不达标则回炉修锚点/校准。
5. **可选 judge 辅助上量**：用 LLM/VLM judge 对客观/半客观项批量打分，但须先用人工校准集校准，且事实核查用**独立外部参照**（重新检索/用户上传源），不依赖被测工具的中间产物。
6. **公开原始数据**：题集、每项分、评分者、时间戳、工具版本全部留痕可复现。

## 7. 测试协议（题集设计）

结论要中立，题集就必须**公开、固定、分层**，且对所有工具用**完全相同的提示词**。

**分层维度（建议每格 ≥ 1 题，规模化时加密）：**
- **体裁**：商业路演 / 工作汇报 / 教学课件 / 产品发布 / 数据报告 / 个人分享。
- **输入形态**：一句话命题 / 详细 brief / 长文档转 PPT / 数据表转 PPT / "输入即大纲"。
- **难度**：常规 / 强时效（需联网检索） / 强源材料忠实（给定资料不得跑偏） / 复杂数据可视化。
- **语言/地域**：中文为主，可扩展多语。

**执行要点：**
- 同题同词、同一时间窗内跑完，记录各工具版本与时间戳。
- 每页渲染截图 + 提取文字，作为标准化评分输入。
- 题集与提示词随报告一并公布，任何人可复评。

## 8. 三类使用者怎么用（使用手册）

| 使用者 | 用哪档模式 + 权重 | 怎么用 | 它带来什么 |
|---|---|---|---|
| **自媒体 / 测评人** | 模式 A + 自媒体档 | 拿公开题集横评几家，出总分 + 雷达图 + "最差项翻车实录" | 内容有据、结论可复现 → 成为标准的**社会证明** |
| **工具开发者 / 第三方** | 模式 B + 技术档 | 盲评、多人、公开原始数据、复现他人结论 | 无法被指"不公" → 给标准**技术合法性** |
| **企业采购决策者** | 模式 B + 采购档（用**自己的**题与场景） | 自评或验收各家；把维度雷达 + 数据安全/可移交/成本明细直接写进采购说明 | **自己测、自己信**：结论因中立公开而无法被推翻，采购备忘录自然成文 |

> 对企业采购者尤其关键：本标准不替你结论。你用公开中立的尺子、你自己的题、你在意的权重档，亲手测出各家在"你真正在意的轴"上的高下——这个结论，别人（包括标准的发起者）都动不了。

## 9. 治理与版本

- **中立托管与命名。** 为避免被视为任一厂商的营销物，建议以中立名义托管（独立仓库/社区），名称与所有权与具体厂商解耦。
- **利益冲突披露。** 任何评测报告须声明评测者与被测工具的利益关系；利益相关方的评分须与独立评分交叉核对后方可采信。
- **版本化与可追溯。** 维度、锚点、权重档、硬否决清单均语义化版本管理；每次修订留变更记录与理由。
- **开放修订。** 接受社区对锚点与题集的提案；重大修订经公示。
- **防漂移。** 若引入 judge 辅助，定期用人工校准集体检，防止 judge 随模型更新走偏。

## 附录 B｜术语
- **O / H / S**：客观可测 / 半客观 / 主观。
- **硬否决**：一票否决短板，触发即封顶，不被高分买单。
- **灾难维度**：某维度低于其满分 60%，须标红。
- **一致性（ρ）**：多评分者之间的相关性，衡量评分可信度。
